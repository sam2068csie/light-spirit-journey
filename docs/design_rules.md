# 光靈的旅程：出題與玩法原則（檢查清單）

做新關卡、改題目、做終焉之塔之前先讀一遍。做完之後照最後的「交付前檢查清單」逐項檢查。

- 這份文件記的是**使用者試玩之後交代的規則和決定**。括號裡的日期是決定的時間，有疑問以使用者最新的說法為準。
- 標 **【自動】** 的項目有測試會擋（測試名稱寫在後面）。其他的要自己看截圖、讀題目檢查。
- 各單元自己的進度約定（哪一關先不教什麼）寫在第 6 節。延後到終焉之塔的題型另外記在 `docs/line_tower_backlog.md`。
- 規則有新增或改變時，更新這份文件。

## 1. 玩法：讓它像遊戲，不像作業

### 1.1 不要用「直接挑戰」（2026/11/06）

不要一開始只問最後答案、卡住了才展開步驟。
學生會覺得「我沒辦法一步算出來，我好笨」。題目一律一步一步帶著做。

### 1.2 看得到的後果（2026/11/06）

答對了，世界有反應。答錯了，看到錯的結果，不只是紅字。
引擎已經做好的後果（`line_level.gd`），新的題型也要有類似的東西：

| 操作 | 答對 | 答錯 |
|---|---|---|
| 點選格子點 | 那一點像燈標一樣亮起來 | 閃一下就熄掉，提示 x、y 偏大還是偏小 |
| 滑桿（直線） | 直線上一塊一塊鋪上木板 | 直線閃紅，木板掉進水裡 |
| 滑桿（圓） | 圓規轉一圈把圓畫出來 | 圓晃一下就散掉 |
| 點選區域 | 稻子一株一株長出來 | 塗錯的那幾塊枯掉 |
| 直線碰到圓（C6 起） | 交點濺起漣漪，滑桿讀數顯示交點個數 | 同左（個數不對一眼就看得出來） |
| 直線剛好相切（C7 起） | 切點亮起一盞燈（plane 的 `lamps`） | 還在割或碰不到：只有漣漪或什麼都沒有 |
| 動點走一圈（C8 軌跡） | 走過的地方留下光點（`trail`），做完整圈連成軌跡 | — |
| 軌跡要拿掉的點（C8） | 空心的點（`hole`） | — |

答完一步之後，圖上要補畫那一步的結果（例如求出的直線、臨界的兩條線），讓學生看到自己算出來的東西。

### 1.3 先動手、再解釋（保留試作）

可以先讓學生操作（瞄準光線、轉動直線、推動滑桿），打中了或觀察到了，再問為什麼。
例如 C3 先瞄準光線，C6「繞著燈柱轉的光」先轉轉看再問最長、最短的弦。
但 C3 的光線題最後改回「先推導」（2026/11/06），所以要看題目決定，不是每題都要先試作。

### 1.4 學生要自己列式（直線與圓 C1 試玩）

觀念判斷完之後，**不要直接把算式寫好給學生**，只讓他們照著算答案。這樣是跳步，也培養不了列式的能力。

- 用方程式填空（模板裡挖空）讓學生參與列式。多幾個步驟沒關係，但每一步都要是推出答案必經的（1.7）。
- 一次只做一步，做完才出現下一步。
- 可以互換順序的格子用 `groups`。其他也算對的整組答案用 `alts`。負數填進去顯示成 (−2)（`paren`）。

### 1.5 提示和輔助線不能洩漏答案

- 答錯的提示給方向或回想的線索，不直接給答案。
- 圖上的輔助線（虛線、垂線）如果會碰到圓，要寫 `"nohit": true`。不然交點漣漪會先把答案標出來（C6 修過）。
- 要學生自己找的點，在問之前不要先畫出來。

### 1.6 操作

- 點格子的步驟要能縮放：手機雙指捏合，電腦用滑鼠滾輪（**【自動】** `guards`）。
- 圓心可以直接在方格上拖動，和多項式的平移一樣，滑桿同時跟著動（C5，2026/11/06）。
- 參數題用滑桿調參數（C2，2026/11/06）。


### 1.7 每一步都要是回答這一題必要的（R1 試玩，2026/11/14）

做完一題，對每一步問：**拿掉這一步，還答得出題目問的問題嗎？** 答得出來，這一步就拿掉。

- **觀念題直接問觀念，不要先算。** 「0.3 和 0.31 之間有幾個有理數」靠稠密性就能回答，先算兩次中點是多餘的（R1 兩根柵欄之間）。
- **題目（eq）要寫出要回答的問題。** 只寫條件、不寫問題（「a < b < c，abc > 0」），學生不知道後面的步驟在幹嘛。一題問好幾件事，就寫「下面哪些一定成立」「回答下面三題」，審判卡就是這些問題本身。
- **答案出來就結束，不要再換個方式問一次。** 算出 x = 1 就知道 0.\ol{9} = 1，後面再判「0.\ol{9} 比 1 小一點點」是重複的。下一步的審判卡不能只是重述上一步的結論（c > 0 已經寫在推導紀錄裡了）。
- **別的觀念不要塞進來。** 「怎麼畫出 √6」不需要拖動 C 看哪裡最長、不需要 \frac{a + b}{2} ≥ √ab。那些留給它自己的題目（R4）。
- **可以留下的：** 推出答案的每一個中間步驟（1.4 說的「多幾個步驟沒關係」指的是這種，把一個必要的推導拆小），判 ✕ 之後找反例（證明為什麼不成立），答對後的世界反應（不用作答）。

## 2. 題目內容

- **不照抄講義、考題**：數字和情境都要重新設計。
- **錯的選項要絕對錯**：任何一種合理的讀法下都不能是對的。
  例如相割的範圍，k < 25 是錯的選項，因為它包含 k = −30（那時候是相離）。寫錯的選項時，想一下「有沒有哪個情況它會對」。
- **數字要小**：坐標方格不要畫得太大，題目的數字盡量讓圖落在 −10～10 左右（C6，2026/11/07）。
- **數字要用程式驗算**：每一關都寫驗算程式（交點、距離、面積、範圍的端點），題庫開頭註明。
- **計算太複雜的以觀念為主**：計算為輔。計算量太大的放到終焉之塔或拿掉。
- **還沒教的方法不能用**：照單元的進度（第 6 節）。
- **延後的題型要記下來**：講義有、但這一關沒放的題型，寫進 `docs/line_tower_backlog.md`，每做完一關就更新。
- **份量不用刻意一樣**：每一關的題目數量合適就好（C2，2026/11/06）。

## 2.5 判分：其實也對的寫法都要算對（2026/11/07）

學生寫出正確但和「標準答案」形式不同的答案，不能判錯。

**引擎已經自動處理的**（`step_level.gd` 的 `_fill_submit`）：
- 分數、小數、沒約分的分數都算同一個數：\frac{6}{8} = 0.75 = \frac{3}{4}。
- 有根號的格子會化成最簡再比：√80 = 4√5、\frac{1}{√3} = \frac{√3}{3}。
- **正負號不影響的格子**：`[0]^{2}`、`±[0]`（`∓[0]`）、`|[0]|`、`|[0]m|`，填正的、負的都對。

**出題時要自己標的**：
- 可以互換順序的格子：`groups`（例如 m = [0] 或 [1]、3 × 6 寫成 6 × 3）。
- 方程式的係數、分點公式的權重：`mode: "prop"`，成比例就對（\frac{2A + 6B}{8} = \frac{A + 3B}{4}、2x − 2y = 0 = x − y = 0）。
- 其他整組也對的答案：`alts`（例如斜率寫成 \frac{y₁ − y₂}{x₁ − x₂}）。
- 答案不只一種、但可以用條件描述的：`check`（格子的值叫 s0、s1…）。例如：
  - 點斜式：用直線上**任何一點**都對，不一定要用題目說的那一點。
  - 共線：用另一個已知點列斜率也對。
- 點格子、滑桿：題目要說清楚是哪一個（例如「上方的那一個」「k 是正的那一條」），不然另一個也對的答案要算對。
- 拼積木（多項式 P3、P4）：項的順序、因式的順序本來就不限。積木裡如果湊得出**另一種也對的假設**（例如用另一個除式和它的餘式來設），一定要寫進 `alts` 和 `alt_msg`：拼到時只提醒「這樣也對，不過這一題請用…」，不扣能量。後面的步驟都是照標準假設算的，所以不直接放行。
- 對數的「施放法則」：錯的法則要真的用不上。例如 log_{9} 27、1 / log_{2} 3 用換底也算得出來，換底就不能當錯的選項；log 50 拆成 log 100 − log 2 也行，相減就不能當錯的選項。
- 觀念卡：可以互換的空格寫 `swap`。答案文字相同、但其實可以互換的兩格（例如「一邊 > 0、另一邊 < 0」），改寫成只有一種填法。

**平移量、疊合的角度、相位**：只收題目要的那一個值（最小的平移量、指定範圍裡的角），差一個週期的答案（例如 2 sin(x − π/3) 填成 sin(x − 7π/3)、cos(x + π/4) 填成向右 7π/4）**不算對**（使用者 2026/11/07）。題目要寫清楚範圍或「最小」，讓答案只有一個。

**終焉之塔**（`boss_tower.gd` 有自己的填空判斷 `fill_slots_ok`）：數值一樣就對（分數、小數、沒化簡的根號都可以），± 裡的格子正負號都可以。它沒有 `groups`、`prop`、`set`：出題時要把式子寫成只有一種填法（例如兩根「由小到大」、係數的首項固定）。

**終焉之塔的題量**：每次爬都要有新鮮感，題目要遠多於層數（使用者 2026/11/08）。塔頂固定 30 層；試煉大題要 12 題（一輪出 6 題），其中難度 2 的至少 4 題（第 5、10 層用）；每一題做 3 組數字（`vars`）。塔會記住前幾輪出過的「題目#數字組」（存檔 `tower_seen`），先出沒看過的。數字組用程式產生、assert 驗算，不要手抄（做法見第 7.5 節）。

**測試**：`tests/run_tests.sh answers` 會真的跳到那一步填入另一種寫法，確認算對，也確認錯的答案還是判錯。新增「另一種也對的寫法」時，把例子加進 `tests/test_answers.gd` 的 CASES（拼積木加進 BLOCKS）。

## 3. 寫法與符號

| 規則 | 正確 | 不要 |
|---|---|---|
| 除法寫成分數 | \frac{a}{b} | a ÷ b **【自動】** `markup` |
| 玩家看得到的文字不用分號 | 逗號、句號，或拆成兩句 | 「；」 **【自動】** `markup` |
| 根號要有橫線 | √(x^{2} + 1)（會自動補成 √{…}） | 畫不出橫線的根號 **【自動】** `markup` |
| 線段長加上橫線 | \ol{AB} | AB（當長度用的時候） |
| 循環小數的循環節加上橫線 | 1.2\ol{36}、0.\ol{9} | 1.2363636…、點點的寫法 |
| 分數裡面盡量不要再放分數，拆成兩步寫（3b = \frac{9a + 3c}{4} ⇒ r = …） | 2b = \frac{4a + 2c}{3} ⇒ q = \frac{7a + 2c}{9} | \frac{a + 2 × \frac{2a + c}{3}}{3}（排版會寫成一行：(2a + c)/3，比較難讀） |
| 數系、集合符號直接打字 | ℚ、ℝ、ℤ、ℕ、∈、∉、⊂、∪、∩、∅ | Q、R（普通字母當數系） |
| 點到直線的距離 | d(P, L)、d(K, L)、d(O, L) | 單獨寫 d **【自動】** `markup`（C1～C8） |
| 兩平行線的距離 | d(L₁, L₂) | 單獨寫 d |
| 弦心距 | 寫「弦心距」或 d(K, L) | 單獨寫 d |
| 負號 | −（U+2212） | -（減號鍵盤字元） |
| 方程式的首項係數 | 3x + 4y − 2 = 0 | −3x − 4y + 2 = 0 |
| 圓心在原點 | x^{2} | (x)^{2} |
| 係數 1 | x + y | 1x + 1y |
| 滑桿讀數 | 不是分數就到小數第二位，整數不寫 .0 | 10.0 |

- 排版符號要寫對：大括號成對、\frac 後面接兩組 {…}、^ 後面接 {…} **【自動】** `markup`。
- 步驟名稱（顯示在步驟列）不能放 \ol、\frac 這些排版，因為那裡畫不出來。改用文字。
- 角度、根號、分數的寫法和其他單元一致，有疑問先看已經做好的關卡怎麼寫。

- 「；」和 ÷ 這條規則**全部單元都適用**（2026/11/07）。舊的文字已經全部改掉（指對數、多項式、三角函數、大地圖、介面）。
- `markup` 測試會掃題庫、速算、觀念卡、章節卡、腳本裡的字串常數和舊的 JSON 題庫。**寫在函式裡的介面文字（教學、提示、按鈕）測試掃不到**，要自己檢查。
- 例外：`math_text.gd` 的斷行標點表，和三角函數拼公式用的 ÷ 積木（會自動變成分數模式，畫面上看不到）。

## 4. 版面

- **圖上不放中文標籤**：點、直線只用字母和數字（P、L、M(1, 2)）。
- **選項一行放得下**：太長就縮短文字，或把說明移到題目裡。
- **倒數計時用 `UITheme.clock()`**：一分鐘以上寫 15:00，一分鐘以內寫 45 秒；剩 10 秒以內變紅色。
- **同一個畫面只有一隻光靈**：新手教學、提示框上已經有光靈時，關卡的小助手不說話；小助手在頂端列說話，不蓋住題目。
- **是非題的選項位置固定**：「對、正確、是、成立、符合、在、能、有解……」在左，「錯、錯誤、不是、不成立……」在右，不跟著打亂；不等號方向題「不變」在左、「變向／反向」在右 **【自動】** `banks`。
  寫在 `data/levels/engine/choice_order.gd`；選項可以帶說明（「成立（0 > −1）」），只看開頭那個詞。新的肯定／否定詞要加進 `PAIRS`。
- **按鈕、卡片、文字不能超出畫面或卡片** **【自動】** `play`（真的玩一次，量每一個控制項）。
- **觀念卡選項裡的分數不能超出按鈕** **【自動】** `concepts`。
- **填空框不能蓋住坐標方格**：放不下就把一步拆成兩步（C2 截距、C3 撞球、C4 面積都拆過）。
- **章節卡的文字不能把按鈕擠出卡片**：寫短一點。
- **圖上的標籤不要互相重疊**：點的名字、軸的 x、y、刻度、圓心的名字都要錯開（每一關都要看截圖檢查）。
- **背景要淡**：有主題感，但不搶題目和圖形。

## 6. 各單元的進度約定

### 高一「直線與圓」（C1～C8＋終焉之塔）

- **C3**：同側、異側只用**看圖**判斷，不提代入的正負。C4 才正式教「代入 ax + by + c 看正負」。
- **C3**：內心題只做直角三角形（兩邊在坐標軸上）。一般三角形的內心放塔裡。
- **C4**：**不收線性規劃**，主線和塔都不放（2026/11/06）。
- **C5**：「恰可決定一圓」放 C5。和兩軸相切、過一點的圓，兩個圓都要畫（2026/11/06）。
- **C6**：**不用判別式**，直線和圓的關係一律用 d(K, L) 和 r 比。半圓與直線的交點個數放 C6（2026/11/07）。
- **C7**：先用「切線 ⊥ 半徑」推，第二題再給替換公式 x₀x + y₀y = r^{2} 當捷徑（2026/11/07）。
- **C7、C8**：**不收圓冪**（課綱刪掉了），主線和塔都不放。切線段長只用畢氏定理 √(\ol{PK}^{2} − r^{2})（2026/11/07）。
- **C8**：圓系（C + kL = 0、C₁ + kC₂ = 0）、公共弦、外公切線都放 C8（2026/11/07）。
- 延後到塔的題型：`docs/line_tower_backlog.md`。

### 高一「數與式」（R1～R8＋終焉之塔，規劃見 `docs/num_plan.md`）

- **順序照講義的重點一～八**，一關一個重點。乘法公式國中學過，不用為了它換順序（2026/11/13）。
- **每一關都分 2 章，一章最多 12 題**（2026/11/13）。
- **三項的算幾不等式（a^{2}b 型）不收**，主線和塔都不放（2026/11/13）。
- R5：a + b、ab 有理 ⇒ a^{3} + b^{3} 有理的題目放塔，主線只放用國中公式判斷得出來的（2026/11/13）。
- 反證法：用「把證明的句子排順序，再找出矛盾在哪一句」代替寫證明（2026/11/13）。
- 延後到塔的題型：`docs/num_tower_backlog.md`。
- **原野元件**（`data/levels/num/num_field.gd`）：題目的 `field` 放風車 `mill`、數線 `nline`、質因數積木 `blocks`，寫法見檔案開頭。
  比大小、排順序的題目，數線上的點要等學生排好之後才出現（`at` 寫成排序那一步），不然一看就知道順序（R1，2026/11/13）。
  尺規作圖的答案不要是整數，免得從坐標方格上直接讀出來（R1 平行的柵欄，2026/11/13）。
- 速算可以混用填空和按鈕（`choices`）：`test_real` 會點按鈕（先點錯一次）。

## 7. 交付流程

1. 新增腳本之後執行 `python3 tools/gen_paths.py`。

### 7.5 終焉之塔怎麼出題（2026/11/09）

四座塔（直線與圓、多項式、三角函數、指數與對數）的題目都是**程式產生**的，`data/levels/tower/*_tower_data.gd` 不能手改。

**資料夾**
- `tools/towerlib/`：共用工具。
  - `lib.py`：數字和式子的格式、選擇題／填空／審判卡、坐標圖。
  - `tlib.py`：π 的倍數、特別角、a + b√n（`Q`）、數值驗算（`chk`、`cardc`、`roots_in`、`ext`）。
  - `gen.py`：產生器。
  - `compare.py`：把手寫題庫改成模板時，比對第 1 組。
- `tools/<塔>_tower/t_*.py`：這座塔的題目模板。
  - 塔名是 line、poly、trig、explog。
  - 每座塔可以有自己的工具（`plib.py`、`elib.py`）。

**一題的寫法**
- 一題是一個模板函式：參數是數字，傳回一組完整的題目。
- 每個模組的 `items()` 傳回 `[[第 1 組, 第 2 組, 第 3 組], …]`。
  - 第 1 組是題目本身，其他組進 `vars`。
  - `id`、`kind`、`tier`、`title`、`tmul` 每一組都要一樣，`gen.py` 會擋。
- **答案、提示裡的算式、錯的選項，全部由程式算**，不要手寫數字。
- 每一組都要 assert 驗算，至少驗這些：
  - 答案代回去成立（或和數值計算一致，`chk`、`near`）。
  - 錯的選項真的錯（`uniq` 擋重複）。
  - 審判卡用 `cardc(敘述, 真假, 理由, 程式算的真假)`，真假不一致就擋。
  - 範圍、根的個數用數值掃過（`roots_in`、`ext`、數線題逐段檢查）。
  - 圖畫得下（點在 x、y 範圍裡）。
- 數字組要挑得像**另一題**：換條件、換象限、換題型的一個分支（例如頂點在範圍內／外），不要只換一個倍數。
- 負號可以直接寫 `-3`：`gen.py` 會把題目文字裡的負號換成 −。畫圖的式子 `f` 保留 `-`，`PI` 會換成數字。

**改完要做的事**
1. `python3 tools/towerlib/gen.py <塔>`：重新產生。四座一起產生就不加塔名。
2. 第 7 節的測試，再加上：
   - `tests/run_tests.sh gen`：檢查 `*_data.gd` 和產生器一致。**【自動】**預設的測試、CI 都會跑。手改 `.gd` 會被擋下來。
   - `UNITS=<單元> TMODE=items,wrong ALLSHOTS=1 SHOTS=… xvfb-run -a tests/run_tests.sh tower`：每一組數字都真的作答一次（先答對、先答錯）。檔名是 `<id>_v<組>_<步驟>`，`ONLY=id1,id2` 只跑改到的題。
   - `UNITS=<單元> TMODE=pick,lose … tower`：模擬連爬 8 次，看前幾次有沒有重複；心用完的流程。
3. 看截圖：有圖的題目、新題，每一組都要看。
